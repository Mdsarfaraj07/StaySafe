# StaySafe – Full Stack (React + Spring Boot + MySQL)

```
staysafe-fullstack/
├── docker-compose.yml        # optional MySQL container
├── backend/                  # Spring Boot 3 (Java 17, Maven)
│   └── src/main/java/com/staysafe/
│       ├── config/           # Security, JWT, CORS, DataSeeder
│       ├── controller/       # Auth, Property, Booking, Favorite, Notification, Ticket, Owner, Admin
│       ├── dto/              # request/response records + Mapper
│       ├── model/            # JPA entities
│       ├── repo/             # Spring Data repositories
│       ├── service/          # NotificationService
│       └── exception/        # ApiException + global handler
└── frontend/                 # React + Vite + Tailwind
    └── src/api/              # fetch client (JWT) + service functions
```

## 1. Start MySQL
Either use the container:
```bash
docker compose up -d
```
or your own MySQL 8 – then set `DB_USERNAME` / `DB_PASSWORD` (defaults: `root` / `root`).
The `staysafe` database and all tables are created automatically on first start.

## 2. Start the backend (port 8080)
```bash
cd backend
mvn spring-boot:run
```
Environment variables (all optional): `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD`, `JWT_SECRET` (>= 32 chars), `CORS_ORIGINS`.

## 3. Start the frontend (port 5173)
```bash
cd frontend
npm install
npm run dev
```
Vite proxies `/api` to `http://localhost:8080`. For production set `VITE_API_URL` (see `.env.example`).

## What works end to end
- Register / login with JWT, role-based access (Customer, Owner, Admin)
- Browse and filter verified listings, property details, reviews and ratings
- Date-based booking with payment step, cancellation (48h rule), receipts
- Favorites, support tickets (admin replies / resolves), profile editing
- Owner: add listings (go to admin review), incoming guests, earnings (10% platform fee)
- Admin: stats, approve / reject listings, ticket desk, enable / disable users
- Real notifications generated by every action (polled every 30s)

## API summary
| Area | Endpoints |
|---|---|
| Auth | `POST /api/auth/register`, `POST /api/auth/login`, `GET/PUT /api/auth/me` |
| Properties | `GET /api/properties?q&type&maxPrice`, `GET /api/properties/{id}`, `GET/POST /api/properties/{id}/reviews` |
| Bookings | `POST /api/bookings`, `GET /api/bookings/me`, `PUT /api/bookings/{id}/cancel` |
| Favorites | `GET /api/favorites`, `POST /api/favorites/{propertyId}` (toggle) |
| Tickets | `POST /api/tickets`, `GET /api/tickets/me` |
| Notifications | `GET /api/notifications`, `PUT /api/notifications/{id}/read`, `PUT /api/notifications/read-all` |
| Owner | `GET/POST /api/owner/properties`, `GET /api/owner/bookings`, `GET /api/owner/stats` |
| Admin | `GET /api/admin/stats`, `GET /api/admin/properties/pending`, `PUT /api/admin/properties/{id}/approve|reject`, `GET /api/admin/tickets`, `PUT /api/admin/tickets/{id}`, `GET /api/admin/users`, `PUT /api/admin/users/{id}/toggle` |

## Notes
- Payment is simulated. To go live with Razorpay: add an endpoint that creates a Razorpay order, open Razorpay Checkout in `BookingPaymentView`, then verify the signature in `BookingController.create` and store the real payment id in `paymentRef`.
- Change `JWT_SECRET` and the seeded passwords before deploying.
- `spring.jpa.hibernate.ddl-auto=update` is convenient for development; use Flyway/Liquibase migrations in production.
